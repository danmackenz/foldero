- [ ] **Step 1: Dispatch claude-code-guide agent**

Ask it directly: "For Claude Code 2.1.276, (1) is `files` still the current field in plugin.json for scoping what gets packaged, or has it been renamed/superseded — give exact current syntax; (2) do Claude Code plugins support a `hooks/` directory or a `hooks` key in plugin.json today, and what's the exact schema (event names, matcher format, command type); (3) is there a plugin-scoped memory mechanism that loads content only when a specific plugin's skill runs, as opposed to a project-root CLAUDE.md which loads for every session in that directory regardless of which plugin is active."

- [x] **Step 2: Record findings verbatim**

**(a) `files` field:** Does NOT exist. Plugins declare components via explicit fields (`skills`, `commands`, `agents`, `hooks`, `mcpServers`, `lspServers`, `experimental.monitors`) pointing to directories/files, auto-detected on default layout. **Critically: for a git-source install, the entire repository is cloned to the user's disk regardless of what's declared** — there is no `files` allowlist and no runtime filter. The only exclusion lever is a `git-subdir` marketplace source type (sparse clone of one subdirectory of a monorepo) — not a per-file filter, and it requires restructuring which directory the marketplace entry points at. **Spec §1-2-5's premise (add a `files` array) is factually wrong for this plugin system — Task 2 as originally written cannot be implemented as specified.**

**(b) Hooks:** Fully supported, `hooks/hooks.json` (or inline in `plugin.json`). Event names include `PreToolUse`, `PostToolUse`, plus others (`SessionStart`, `UserPromptSubmit`, `PostToolUseFailure`, etc.). Hook types: `command`, `http`, `mcp_tool`, `prompt`, `agent`. Command type: `{"type": "command", "command": "...", "args": [...]}`. Matcher: exact string, regex, or omitted (match-all). `${CLAUDE_PLUGIN_ROOT}` resolves to the plugin's install directory and is available in hook commands. **Task 13's draft hooks.json matches this schema** (event names, command type, `${CLAUDE_PLUGIN_ROOT}` usage all confirmed correct).

**(c) Plugin-scoped memory:** Does NOT exist. Project `.claude/CLAUDE.md` loads for every session in that project tree regardless of active plugin — cannot be scoped. Agents support a per-agent `memory` field (agent-specific only, not plugin-wide). `${CLAUDE_PLUGIN_DATA}` is persistent storage, not an auto-loaded context mechanism. **This confirms the approved BRAIN.md design is correct as specced** — it was never designed to rely on automatic context injection; it's read explicitly by skill/agent logic on invocation (Praeco/Decurion read the INDEX section when they run), which sidesteps this limitation entirely. §14's investigate-and-report is fully answered: no native plugin-scoped memory exists, so BRAIN.md's skill-read-on-demand design (not a project-root CLAUDE.md, not a nonexistent plugin-memory feature) is the right call.

Source: https://code.claude.com/docs/en/plugins.md, https://code.claude.com/docs/en/plugins-reference.md, https://code.claude.com/docs/en/hooks.md, https://code.claude.com/docs/en/plugin-marketplaces.md (current as of 2026-09-18).

- [ ] **Step 2: Write the move-verification hook**

Create `hooks/verify-move-mechanics.sh`:
```bash
#!/usr/bin/env bash
# ponytail: shells out per-move rather than batching; fine at Foldero's per-run item counts, revisit if a single run routinely moves 1000+ items.
set -euo pipefail
SRC="$1"
DST="$2"
if [ -e "$SRC" ]; then
  echo "VIOLATION: source still present after move: $SRC" >&2
  exit 1
fi
if [ ! -e "$DST" ]; then
  echo "VIOLATION: destination missing after move: $DST" >&2
  exit 1
fi
exit 0
```

- [ ] **Step 3: Write the run-lock enforcement hook**

Create `hooks/verify-run-lock.sh`:
```bash
#!/usr/bin/env bash
set -euo pipefail
ROOT="${1:-.}"
LOCK="$ROOT/_LOGS/.run-lock"
if [ -f "$LOCK" ]; then
  LOCK_AGE_SEC=$(( $(date +%s) - $(stat -f %m "$LOCK" 2>/dev/null || stat -c %Y "$LOCK") ))
  if [ "$LOCK_AGE_SEC" -lt 21600 ]; then
    echo "VIOLATION: fresh run-lock present ($LOCK_AGE_SEC s old) — another mutating skill is active on this root" >&2
    exit 1
  fi
fi
exit 0
```

- [ ] **Step 4: Write the BRAIN.md append hook**

```bash
CONFIDENCE="${4:-}"
BRAIN="$ROOT/BRAIN.md"
[ -f "$BRAIN" ] || exit 0
{

  echo "- decision: $DECISION"
  echo "- confidence: $CONFIDENCE"
} >> "$BRAIN"
exit 0
```
